# Спецификация MVP: календарь звонков

Сервис бронирования календаря: владелец публикует типы встреч, гость записывается на свободное время. Объём MVP — ровно сценарий из `README.md` (шаги 1–13).

Термины — по `GLOSSARY.md`: Владелец, Гость, Тип встречи, Запись, Слот, Окно записи.

## Доменная модель

### Тип встречи

Поля:

- название — обязательное, непустое, до 100 символов; уникальное: сравнение без учёта регистра и с обрезкой пробелов по краям; при конфликте создание отклоняется ошибкой валидации на поле «название»;
- описание — необязательное, до 1000 символов;
- длительность — выбор из 15, 30 или 60 минут;
- id — технический, числовой.

Тип встречи только создаётся: редактирования и удаления нет. Запись ссылается на тип, снимок его полей не хранится.

### Запись

Поля:

- тип встречи (ссылка);
- дата и время начала (старт слота); конец вычисляется из длительности типа, отдельно не хранится;
- имя гостя — обязательное, непустое, до 100 символов;
- email гостя — обязательный, с проверкой формата;
- заметка — необязательная, до 1000 символов;
- id — технический, числовой.

Состояний и переходов нет: запись существует с момента бронирования, не отменяется и не переносится. «Прошедшая» — не состояние, а следствие текущего времени: такая запись выпадает из списка предстоящих.

## Слоты и окно записи

- Сетка стартов — каждые 15 минут (9:00, 9:15, 9:30, …), одинакова для всех типов встреч.
- Длина слота равна длительности типа встречи.
- Слот целиком умещается в дневных границах 9:00–18:00: последние старты — 17:45 для 15 минут, 17:30 для 30 минут, 17:00 для 60 минут.
- Окно записи — скользящие 14 календарных дней включая сегодня; выходные не исключаются; уже прошедшие сегодняшние слоты недоступны.
- Часовой пояс — один фиксированный пояс владельца, задаётся в конфигурации (по умолчанию `Europe/Moscow`); границы 9:00–18:00 заданы в нём, гость видит время в нём же, в UI — подпись пояса; конвертации в пояс гостя нет.

## Занятость

- Слот «Занято», если его интервал `[старт, старт + длительность)` пересекается с интервалом любой существующей записи (любого типа встречи).
- Стык-в-стык разрешён: запись 10:00–11:00 не занимает слот с 11:00. Буферов между встречами нет.
- Статусов ровно два: «свободен» и «Занято»; прошедшие слоты и слоты вне окна записи гостю не показываются.
- Статусы на экране — снимок на момент загрузки; гонку двух гостей решает сервер при бронировании: проигравший получает `409`.
- Запись занимает пересекающиеся слоты навсегда (в пределах жизни in-memory хранилища).

## Хранение и данные

- In-memory репозитории внутри Spring-приложения, без базы данных (ADR-0001); данные теряются при перезапуске; репозитории прячутся за интерфейсами, чтобы переход на базу данных был дешёвым.
- Seed-данных нет: хранилище стартует пустым, единственный источник типов встреч — создание владельцем в админке.

## API

JSON, camelCase, префикс `/api`; id — числовые; длительность — числом минут (15/30/60).

### Эндпоинты

- `GET /api/meeting-types` — список типов встреч (гость, шаг 5; админка, шаг 3): `200`, `[{id, name, description, durationMinutes}]`.
- `POST /api/meeting-types` — создание типа (шаг 2); тело `{name, description?, durationMinutes}`; ответ `201` с созданным типом.
- `GET /api/slots?meetingTypeId=<id>&date=<YYYY-MM-DD>` — слоты дня для типа (шаг 7): `200`, `[{start, status}]`, где `status` — `"free"` или `"busy"`, `start` — ISO 8601 с offset пояса владельца, `date` — в том же поясе; прошедшие слоты не возвращаются; дата вне окна записи — пустой массив, не ошибка.
- `POST /api/bookings` — бронирование (шаг 9); тело `{meetingTypeId, start, guestName, guestEmail, note?}`; ответ `201` с созданной записью.
- `GET /api/bookings` — предстоящие записи владельца (шаг 13): `200`, полный список по возрастанию старта, без пагинации.

Объект записи в ответах — с вложенным типом: `{id, start, guestName, guestEmail, note, meetingType: {id, name, durationMinutes}}`.

### Коды ошибок

- `400` — ошибки валидации (включая конфликт уникальности названия типа); тело `{"errors": {"<поле>": "<сообщение>"}}`;
- `404` — ссылка на несуществующий id;
- `409` — слот уже занят (гонка двух гостей); тело с кратким сообщением.

Вне API MVP: пагинация, фильтры, авторизация.

## Фронтенд

Маршруты: `/` — главная, `/book` — запись, `/admin` — админка; в шапке — «Админка» и «Записаться».

### Мастер записи (`/book`)

Шаги — состояние мастера на одном маршруте, не отдельные URL:

1. **Выбор типа встречи** (шаг 5 ТЗ): карточки типов; типов нет — заглушка «Пока нет доступных встреч», пройти дальше нельзя.
2. **Календарь и слоты** (шаги 6–8): в карточке слева — поля «Выбранная дата» и «Выбранное время». Кнопка «Продолжить» неактивна, пока не выбрано время. Время — в поясе владельца, с подписью пояса.
3. **Форма** (шаг 9): имя, email, заметка (необязательная). Валидация при нажатии «Забронировать»: имя непустое и до 100 символов, email по формату, заметка до 1000; ошибки — под соответствующими полями. Кнопка «Забронировать» всегда активна. Серверные ошибки валидации (`400`) выводятся у тех же полей.
4. **Подтверждение** (шаг 10): название, дата и время встречи (из тела ответа бронирования).

Ответ `409` при бронировании: сообщение «Это время уже занято» и возврат на шаг выбора слотов с обновлённым списком.

**Календарь:** дни вне окна записи видимы в сетке месяца, но не кликабельны и показаны другим цветом (приглушены); кнопки ← и → листают только месяцы, пересекающие окно записи (назад — не раньше текущего месяца, вперёд — не дальше месяца с последним днём окна); прошедшие слоты не показываются; свободных слотов на выбранную дату нет — заглушка «Нет свободных слотов».

### Админка (`/admin`)

Одна страница с вкладками:

- **«Типы встреч»** (шаги 1–3): список типов; кнопка «Создать событие» открывает форму (название, описание, выбор длительности), «Сохранить» создаёт тип, новый тип появляется в списке; типов нет — заглушка «Пока нет типов встреч».
- **«Предстоящие встречи»** (шаг 13): строка — название типа встречи, дата и интервал времени, имя гостя, email гостя, заметка (если заполнена); только предстоящие записи, по возрастанию старта, без пагинации; записей нет — заглушка «Предстоящих встреч нет».

Формат даты и времени у владельца: `10.11.2026, 09:00–09:30 (Europe/Moscow)` — дд.мм.гггг, интервал «начало–конец» (конец = старт + длительность типа), в скобках имя пояса владельца. Тот же формат везде, где владелец видит время.

### Общие состояния

- Загрузка — индикатор на блоке данных (список типов, слоты, список записей).
- Ошибка сети или сервера — сообщение об ошибке с кнопкой «Повторить».

## Вне скоупа MVP

- Отмена и перенос записей, несколько владельцев, авторизация (ADR-0002).
- Напоминания, интеграция с внешними календарями (ADR-0002).
- Редактирование и удаление типов встреч.
- Отображение прошедших записей.
- Конвертация времени в часовой пояс гостя.
- Миграция с in-memory хранилища на базу данных (ADR-0001).
